# 批改指南（grading-guide）

引擎负责客观题的确定性判分；简答题预评分后必须终审。本文是终审与反馈的规范。

## 判分分工

| 题型 | 引擎判分 | 是否终审 |
|---|---|---|
| choice 单选 | 全对得分，否则 0 | 否 |
| choice 多选 | (命中数−误选数)/正确数 比例给分，下限 0 | 否 |
| judge | 布尔精确匹配（兼容 对/错/T/F/√/× 等写法） | 否 |
| fill | 归一化匹配 answers 任一项，或命中 regex | 否 |
| short | 加权关键词覆盖率 × 分值（预评分） | **是，必审** |

## 简答题终审流程

对每个 `needs_review: true` 的结果：

1. **读题与参考答案**：以 `explanation`（完整参考答案）为评分基准。
2. **核对预评分**：关键词覆盖是机械匹配，存在两类误差——
   - 语义等价但字面不同（如"写入性能下降" vs "写入变慢"）→ 引擎可能判缺；
   - 字面命中但语义错误（如只罗列了术语、逻辑不通）→ 引擎可能多给分。
3. **调整分数**：在预评分基础上上下修正，但**不得超过 `max_score`**；
   调整后把 `is_correct` 置为 `score >= max_score * 0.6`（或按满分标准从严）。
4. **留痕**：把终审理由写进 `analysis`，前缀"[终审]"。

## 反馈结构（每题必含）

批改结果 `results[i]` 中，向用户展示时按以下顺序组织：

1. `score / max_score` —— 得分
2. `user_answer` 与 `correct_answer` —— 你的答案 vs 正确答案
3. `analysis` —— 错误分析：错在哪一步（引擎已生成，终审可补充）
4. `explanation` —— 知识点讲解：为什么正确答案成立、背后的原理
5. `knowledge_point` —— 薄弱知识点标签，用于推荐复习方向

## 整卷反馈语规范

- 先给 `summary.total_score / max_total` 与客观题正确率；
- 按 `by_type` 分题型小结；
- 列出 `needs_review_count` 并说明"简答题分数为预评分/终审后分数"；
- 按 `knowledge_point` 归并错题，给出 2–3 条具体复习建议（不写"多做题"这类空话）；
- 语气客观直接，不用"很遗憾""恭喜"等情绪化措辞。

## 常见误判与处理

- **填空题被误判**：优先检查归一化差异（全角/标点/大小写）；若属同义写法
  未收录，应把该写法补进题目 `answers` 后重新批改，而不是手工改分。
- **多选题部分分争议**：引擎规则是 (命中−误选)/正确数，漏选给部分分、
  误选倒扣至 0，属标准规则，向用户说明即可。
- **简答字面命中但答非所问**：终审时回收该要点分数，并在 `analysis` 说明
  "仅罗列术语，未解释机理"。
